# 分发解冻：从个人审计脚本到可分发工具

> 状态：**已决策——解冻。** 本文推翻 `distribution-frozen.md` 的默认结论，并由用户明确授权：
> "除了阶段4，其他全做并打磨漂亮"。
> 上一份决策的**理由**没有被证伪，只是**目标**变了：不是"分发解决不了问题"，而是
> 作者现在要把 shell 补到 mygo 的完整形态，而完整形态包含分发链。

## 1. 被推翻的决定

`docs/decisions/distribution-frozen.md` 的结论是"不分发，且这是优点，不是缺陷"。它在
D0 提出的问题——"分发后它做哪一件 Windows Update / Vantage 做不到、而目标用户又真正
需要的事？"——**至今没有被回答**。本次解冻不声称它被回答了。

解冻的理由是另一条：本仓库的桌面壳已迁移到 mygo 原生 UI（`internal/gui`），mygo 的
`distribution` / `updates` / `github-actions` 是这条壳的组成部分。只取 UI 而弃分发，
等于把壳做了一半。作者选择做全，接受随之而来的产品形态变更。

## 2. 由此改变的不可回退约束

`AGENTS.md` 的"部署形态 = 个人单机审计脚本"**不再成立**。分发尾解冻后：

| 项目 | 之前 | 现在 |
| --- | --- | --- |
| 安装器 | 冻结 | `mygo build` 产出 NSIS 安装器 |
| 升级 | 冻结 | `mygo.Updater` + 签名 release |
| 签名 | 冻结 | Ed25519 更新签名（非代码签名证书） |
| 运行时入口 | 裸 exe + bat | exe / 安装器 / 深链 |

**没有改变**的六条不变量（`docs/spec/invariants.md`），逐条说明为什么不冲突：

1. **确定性 / 零遥测**：更新检查是**用户显式点击**托盘菜单触发的一次 GET，不是后台轮询；
   未配置更新源的构建（开发构建、个人裸编译）`Updater.Enabled()` 为 false，一个包都不发。
   "无隐藏联网"仍成立——隐藏的是"悄悄"，不是"用户要求的"。
2. **证据优先**：未触及。
3. **默认不动**：未触及。
4. **事实分级**：未触及。
5. **审计先于状态变更**：未触及。
6. **设备级回退**：未触及。

## 3. 已知代价（诚实记录）

- **代码签名证书未购置**：更新档是 Ed25519 签名的（mygo 自己的信任链），但 Windows 可执行
  文件本身没有 Authenticode 证书。SmartScreen 会对安装器报警。内部分发可接受，公开发布不行。
- **签名私钥是新的关键资产**：丢失即让已安装用户再也收不到更新；泄露即可向所有用户推任意
  代码。它只存在于 CI secret（`MYGO_UPDATER_PRIVATE_KEY`）与作者本地。
- **`updates.github` 指向的仓库必须真实存在**：在第一个 release 发布前，`Updater.Check` 会
  失败并弹出"检查更新失败"，而不是静默——这是有意的（不假装检查过）。
- **安装位置改变**：安装器装到 `%LOCALAPPDATA%\Programs`，不再是仓库目录里的 `bin\`。裸
  exe 路径（`install_lenovo_drivers.bat`）仍可用，但自动更新只对安装器装的那份生效。

## 4. 变成终态需要什么

- 一个真实的 GitHub 仓库与 `MYGO_UPDATER_PRIVATE_KEY` secret（`release.yml` 已就绪）
- 首个 `v*` tag
- 若要公开分发给陌生用户：Authenticode 代码签名证书，以及重新回答 D0 的问题

在 D0 被回答之前，**本工具仍是作者自用的审计工具，只是现在带安装器和更新通道**。
